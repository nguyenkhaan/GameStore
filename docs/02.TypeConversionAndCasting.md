# Type Conversion and Casting

[Course index](README.md) · [Previous](01.Variables.md) · [Next](03.VarDynamicAndObject.md)

Conversion changes a value from one type to another. C# allows some conversions automatically. Other conversions require explicit syntax and can lose information or fail.

```csharp
int count = 42;
long largerCount = count; // Implicit conversion: every int value fits exactly in long.

double price = 19.75;
int wholePrice = (int)price; // Explicit cast: result is 19.
```

Text is not a number, so use parsing to convert it. `(int)"123"` does not parse text and is not valid C#. Prefer `TryParse` for values that may be invalid, such as user input. The `if` below runs only when parsing succeeds; [lesson 04](04.IfElse.md) explains conditions.

```csharp
if (int.TryParse("123", out int number))
{
    Console.WriteLine(number + 1);
}
```

For reference types, pattern matching safely checks the type before using it:

```csharp
object item = "hello";

if (item is string text)
{
    Console.WriteLine(text.ToUpper());
}
```

`int.Parse` throws for invalid input or a value outside the integer range; `TryParse` reports those failures with `false`.

Casting a reference changes how you access the same object; it does not transform it into a new object. Numeric casts work differently: `(int)19.75` removes the fractional part. Some implicit numeric conversions can also lose precision, such as `int` to `float`. For integer arithmetic and integer-to-integer casts, `checked` makes overflow throw instead of wrapping; it does not prevent floating-point rounding.

## Try it

Read the string `"49.99"` with `decimal.TryParse`, then print the result if it succeeds. Decimal parsing uses the current culture by default, so the accepted decimal separator can differ. For fixed-format text using `.`, pass `System.Globalization.NumberStyles.Number` and `System.Globalization.CultureInfo.InvariantCulture` to `TryParse`.
