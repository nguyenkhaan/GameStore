# Object Initializers

[Course index](README.md) · [Previous](18.TargetTypedNew.md) · [Next](20.CollectionInitializers.md)

An object initializer creates an object and assigns its accessible fields or properties in the same expression.

```csharp
var game = new Game
{
    Name = "Monster Hunter Rise",
    Price = 39.99m
};
Console.WriteLine(game.Name);

public class Game
{
    public string Name { get; set; } = string.Empty;
    public decimal Price { get; set; }
}
```

With the simple class above, it is similar to writing the construction and assignments separately:

```csharp
var game = new Game();
game.Name = "Monster Hunter Rise";
game.Price = 39.99m;
```

The braces after `new Game` are for assigning members. The assignments use `=` because they set values.

The constructor runs before the initializer assigns the members. Object initializers work well for data objects, configuration, and test data. The members must be accessible and settable, for example with a public `set` or `init` accessor.

The project's actual `Game` model also declares `Name` and `Price` as `required`. With its current constructor, callers must include those members in an object initializer; assigning them later does not satisfy the compiler. A constructor marked `[SetsRequiredMembers]` can instead declare that it initializes all required members. `required` enforces initialization at compile time; it does not validate values at runtime. The split example above uses our simpler lesson class.
